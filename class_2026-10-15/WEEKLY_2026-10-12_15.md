### 핵심 개념

- **uv 기반 Python 프로젝트 관리**: `uv init`/`uv add`/`uv run`, `pyproject.toml`·`uv.lock`으로 의존성 고정, `uv pip install`로 넣은 패키지는 `pyproject.toml`에 기록되지 않는다는 점.
- **Git/GitHub 첫 연결**: 사용자 정보 설정 → 첫 커밋 → `main` 브랜치 → 원격 저장소 연결·push.
- **비밀값 관리**: API 키는 `.env`에만 두고 `.gitignore`에 추가, `python-dotenv`로 로딩. 키 확인 시 앞 몇 글자만 출력.

- **OpenAI 호환 API**: Gemini도 `base_url`만 바꾸면 같은 코드로 호출 가능. 강의 노트북의 예전 Gemini 모델명은 404가 나서 최신 모델명으로 바꿔 실행.
- **temperature**: 0이면 거의 같은 답 반복, 높을수록 다양해짐(카페 이름 짓기 예시). 추론 모델(gpt-5-nano 등)은 temperature 조절 불가.
- **토큰**: 한국어가 영어보다 토큰을 더 쓰고, 모델(토크나이저)마다 같은 문장의 토큰 수가 다름. 출력 토큰이 입력보다 훨씬 많을 수 있음.
- **Stateless/Stateful과 Context Window**: 모델은 기억이 없고 앱이 이전 대화를 매번 다시 보내 "기억"을 만든다. 그만큼 토큰이 쌓이고 창 한도에 걸린다.
- **ANN 회귀(표 데이터)**: 거리·날짜 특성 생성 → 범주형 Categorify + 임베딩 → TabularModel 학습 → 손실 그래프 → 저장/불러오기 → 새 데이터 예측.

### 핵심 개념

- **모델 비교 실험 설계**: 같은 프롬프트(4줄 고정 형식), temperature=0, 모델 딕셔너리로 모델 추가는 한 줄, 보내기 전에 토큰 계산, 자동 채점표(형식·제품·조치·지어냄·잘림).
- **클라우드 vs 로컬 트레이드오프**: 로컬(qwen2.5:3b, llama3.2)은 0원·데이터가 PC 밖으로 안 나가지만 정확도·속도가 떨어짐 — 보안 업무에선 "외부 전송 불가"가 조건일 수 있음.
- **환각(지어냄) 통제**: "공지에 없으면 '공지에 없음'이라고 써라" 한 줄이 버전 날조를 막는다는 것을 지시 유무 비교로 확인.
- **청킹**: 문서를 통째로 임베딩할 수 없어서 자름. 고정 크기(토큰 수)/문단(줄 바꿈)/절 제목 기준 세 방식, overlap의 역할. 문단 경계를 지킨 쪽이 검색 결과가 더 좋았음.
- **임베딩·벡터 검색**: `text-embedding-3-small` 또는 로컬 HuggingFace 임베딩, 코사인 유사도 top-k(`np.argsort(-sims)[:k]`), Chroma 벡터 DB. 유사도 점수가 높다고 정답이 아님.
- **RAG**: 검색한 청크를 근거로 LLM이 답하게 하고 출처를 붙임. 문서에 없는 질문엔 "모른다"고 답하게 함.
- **보안 RAG 1단계(security_rag)**: CVE ID 추출 → CVE-CWE 매핑 조회(필터) → CWE 문서 벡터 검색 → 근거 기반 답변. 한계: 역방향(유형→CVE), 제품 버전 판정 불가.
- **보안 RAG 2단계(security_rag_advance)**: CWE(유형 지식, `scope=type`) + 벤더 어드바이저리(사건 지식, `scope=instance`: OSV·Red Hat·KEV) 결합. CVSS·EPSS·KEV 위험도는 그대로 읽고, 버전 판정은 부등호 비교 — **숫자와 버전은 LLM에게 계산시키지 않는다**. `CWE-1021` 같은 정확한 식별자는 벡터 검색이 아닌 조회(lookup)로 처리.

## 10/14 (수) — LLM 파인튜닝: QLoRA로 Qwen2.5-1.5B 학습 (glaive 코드 데이터 / KoAlpaca 한국어)

### 자료

| 파일 | 내용 한 줄 |
|---|---|
| `glaive_colab.md` | Colab(T4)에서 `glaiveai/glaive-code-assistant` Python 질문으로 Qwen2.5-1.5B-Instruct QLoRA 파인튜닝 26단계 |
| `koalpaca_colab.md` | Colab에서 `beomi/KoAlpaca-v1` 한국어 데이터로 같은 모델 QLoRA 파인튜닝, 지저분한 답변 필터링·거절 표현 세기 |

### 핵심 개념

- **QLoRA**: 베이스 모델을 4비트(nf4)로 양자화해 올리고, 작은 LoRA 어댑터(r=8, lora_alpha=16)만 학습 → 저사양 GPU에서도 파인튜닝 가능. 학습 파라미터는 전체의 약 0.14%(약 218만 / 15.5억).
- **라이브러리 버전 고정**: Colab 기본 최신 버전(transformers 5.x, trl 1.x)에선 코드가 `TypeError`로 멈춤 → 검증된 버전으로 고정. bitsandbytes는 torch의 CUDA 버전과 맞아야 함(glaive 노트북은 0.48.2로 변경).
- **데이터 준비**: Python 질문만 선별(glaive), 링크 포함·끝이 잘린 답변 제거(KoAlpaca 21,155 → 20,539건), 프롬프트 템플릿 적용, **256토큰 이하 샘플만** 사용(자르지 않고 제외), 학습 500 / 검증 100건.
- **학습 설정**: SFTTrainer(TRL), learning_rate 2e-4, 1 epoch. T4는 bf16 미지원이라 fp16으로 계산.
- **결과 저장·검증**: 어댑터만 저장(Drive 또는 다운로드), 파인튜닝 모델 답 vs 데이터셋 정답 vs 원래 Qwen 답 비교.

## 10/15 (목) — 도구 호출과 OpenAI Agents SDK, 에이전트 엮기

자세한 내용: [10-15_목/README.md](10-15_목/README.md) (실습 결과), [10-15_목/LECTURE_NOTES.md](10-15_목/LECTURE_NOTES.md) (강의 노트)

### 핵심 개념

- **도구 호출**: LLM은 "무엇을 어떤 값으로 부를지"만 정하고 실행은 코드가 한다. JSON 스키마를 손으로 쓰기 vs `@function_tool` 자동 생성.
- **멀티 LLM 체인**: OpenAI → Gemini → Claude 로 CVE → CWE → 대응 방안. CVE 번호는 LLM이 자주 틀리고(logprobs로 숫자 자리 확신도 60%대), `temperature=0` 은 일관성만 준다 → NVD 조회로 검증하고 원문을 근거로 넣어야 한다.
- **Agents SDK**: Agent·Runner, 도구, 핸드오프, 입력 가드레일, SQLiteSession, `trace` 로 실행 과정 확인.
- **에이전트를 엮는 세 방법**: 코드로 엮기 / 에이전트를 도구로(`as_tool`) / 핸드오프 — 누가 고르고 누가 보내는지가 다르다. 핸드오프는 통제가 넘어가므로 가장 조심해야 한다.
- **보안 일일 브리핑**: 자산 목록 → NVD CVE 수집 → 자산 매칭 에이전트(Pydantic 구조화 출력) → 위험도 평가 에이전트 → 담당자별 HTML 메일. 발송 도구는 담당자 이름만 받고 주소·본문·중복 방지는 코드가 통제. 순서를 코드가 정하는 버전과 LLM 매니저가 정하는 버전 비교.
