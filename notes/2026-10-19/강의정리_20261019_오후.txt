해킹당한 PC에서 '흔적' 찾기 — 사고조사 실습과 보안관제 현장 이야기
2026-10-19 오후 수업 정리 (13:28–16:38)
========================================

한 줄 요약: 해킹당한 PC에 남은 흔적(실행 기록·자동 실행·로그)을 모아 "언제, 무엇이, 어떻게" 일어났는지 거꾸로 추적하는 방법과, 실제 랜섬웨어 사고 사례·보안팀 역할을 배웠다.

1. 수업 흐름
  * 1. (13:28~) 사고조사 수집 도구(CIDER Collector) 결과 보기 — PC 정보, 네트워크 연결, 자동 실행 프로그램
  * 2. (13:44~) 사라지지 않는 흔적 — 파일 기록(MFT), 이벤트 로그, Prefetch, 바로가기(LNK)
  * 3. (14:40~) 레지스트리·USB 연결 기록·썸네일 기록
  * 4. (15:07~) 외부에 노출된 로그인 페이지 찾기, 브라우저 개발자 도구, CTI
  * 5. (15:32~) 실제 사례 — 해외 IP와 통신하는 PC, 키오스크 랜섬웨어
  * 6. (15:43~) 보안팀 역할(PM/PL·관제·CERT·취약점 분석), 오탐 차단 주의, 진로 Q&A
  * 7. (16:28~) 파견관제에서 하는 훈련(디도스·도상훈련)과 국정원 점검

2. 사고조사 증거 수집 — 쉽게 말하면 "범죄 현장 감식"
  * CIDER Collector: PC 안의 흔적을 한 번에 모아 주는 도구 (감식반의 증거 수집 가방)
  * 흔적은 두 종류
     - 휘발성: 전원 끄면 사라짐(지금 연결, 실행 중 프로그램). 현장에서 바로 모아야 의미 있음
     - 비휘발성: 껐다 켜도 남음(파일 기록, 로그). 실제 분석은 대부분 이쪽
  * systeminfo: PC 신분증 — 윈도우 버전, 설치 날짜, 마지막으로 켠 시간, 네트워크 카드
  * netstat -ano: 지금 이 PC가 누구와 통화 중인지 목록. 옆의 PID(프로그램 번호)로 어떤 프로그램인지 찾음
     - 크롬 같은 정상 프로그램이면 괜찮음. 이상한 exe가 악성 이력 있는 해외 IP와 통신 → 악성코드 의심
  * ipconfig /displaydns: PC가 기억하는 "주소록(DNS)". 가짜 주소로 바꿔치기 됐는지 확인
     - 단, 금방 바뀌어서 현장에서 바로 모은 게 아니면 의미 적음

3. 자동 실행 프로그램(Autoruns) — 쉽게 말하면 "아침마다 자동으로 켜지는 알람 목록"
  * PC를 켤 때 저절로 실행되는 프로그램 목록. 작업관리자 '시작프로그램'보다 훨씬 자세함
  * 랜섬웨어·악성코드는 재부팅해도 살아남으려고 여기에 자기를 꼭 등록함 → 꼭 확인
  * 정상 파일인 척하는 경우가 많음 → '만든 회사(게시자)' 칸이 비었거나 이상하면 의심

4. 지워도 남는 흔적들 — 쉽게 말하면 "출입 기록부·CCTV"
  * $MFT: 파일이 언제 만들어지고, 고쳐지고, 열렸는지 기억하는 장부. 가장 많이 보지만 양이 많아 지루한 작업
     - $LogFile과 함께 비교하면 사고 분석에 좋음
  * 윈도우 이벤트 로그: 윈도우의 일기장. 언제 켜졌는지, 누가 로그인했는지(원격 접속이면 상대 IP가 남음)
     - 현장 해킹은 원격접속(RDP)으로 많이 들어옴. 개발자·유지보수 담당이 편하려고 열어 두는 경우가 많기 때문
     - PowerShell 로그 예: 'DownloadFile' 명령으로 XMRig(대표적인 가상화폐 채굴 악성코드)를 내려받은 기록
  * Prefetch(WinPrefetchView로 봄): 실행했던 프로그램 기록. 파일을 지워도 한동안 남음
     - 일정 개수만 저장하고 주기적으로 덮어써짐 → 최대한 빨리 수집
  * 바로가기(LNK) 파일: 문서 바로가기처럼 생겼는데 열면 cmd(명령창)가 실행됐다면 → 위장한 악성 파일
  * 랜섬웨어 판단법: 암호화된 파일이 생긴 시간을 찾고, 그 직전에 무슨 프로그램이 실행됐는지 본다

5. 레지스트리·USB·썸네일 — 쉽게 말하면 "PC의 비밀 수첩"
  * 레지스트리: 윈도우 설정·설치 기록이 담긴 곳. 국산 분석 도구(고려대 개발 REGA)로 수집·분석
     - 실행한 프로그램, 자동 실행, 설치 날짜, 연결했던 USB 목록까지 한눈에 봄
  * 썸네일 캐시(thumbcache): 미리보기 그림 기록 → 어떤 사진이 있었는지 알 수 있음
     - 주로 범죄 수사용. 민감한 자료가 있을 수 있어 일반 해킹 조사에선 잘 안 씀

6. 밖에서 보이는 약점 찾기 — 쉽게 말하면 "우리 집 문이 열려 있나 밖에서 둘러보기"
  * 인터넷 검색 엔진(Shodan 같은)으로 외부에 노출된 로그인 페이지·원격접속(RDP)·테스트 페이지를 찾음
     - 공격자도 이렇게 찾아서 흔한 아이디/비밀번호를 대입함 → 관제도 미리 찾아서 막음
  * 브라우저 개발자 도구(F12): 서버 응답에서 서버 프로그램(nginx 등)과 버전이 보이는지 확인
     - 버전까지 보이면 알려진 약점을 찾기 쉬워짐 → 버전 숨기기 권장
  * 쿠키: 로그인 상태를 기억하는 '입장 팔찌'. XSS 공격은 이걸 훔쳐서 남인 척 로그인함
  * CTI(위협 정보): 악성 IP·공격 수법 정보를 모으는 일. 관제 외에도 다양한 일을 함

7. 실제 사고 사례 — 쉽게 말하면 "실제 사건 수사 일지"
  * 사례 1: 관제 중 한 PC가 해외의 이상한 IP와 445·139·137번 포트(파일 공유용 통로)로 통신하는 것을 탐지 → PC 조사
  * 사례 2: 키오스크 PC 랜섬웨어
     - 파일 이름 뒤에 이상한 확장자가 붙고, "복구하려면 돈 내라"는 안내문 → 전형적인 랜섬웨어
     - 수집 도구 결과를 '수정한 날짜' 순으로 정렬 → 암호화 직전에 실행된 파일을 눈으로 찾아냄
     - 처음엔 그 파일을 못 챙겨서 다시 현장에 가서 수집 후 분석
     - TeamViewer(원격조종 프로그램) 접속 기록과 시간을 맞춰 보고, 그 시간에 접속한 사람을 범인으로 추정

8. 보안팀 역할과 현장 주의점 — 쉽게 말하면 "병원의 진료과 나누기"
  * PM: 계약·전체 관리 담당 / PL: 각 업무 담당 리더 (작은 곳은 PM 혼자 겸함)
  * 관제: 24시간 화면을 보며 공격을 찾아내는 '경비원'
  * CERT: 사고 나면 분석, 평소엔 관제가 편하도록 탐지 규칙 개선(IPS의 Snort 룰, SIEM·SOAR·EDR 다듬기)
     - 관제와 가장 가깝게 일하는 팀. 모르는 건 CERT에 물어보면 잘 알려 줌
  * 취약점 분석팀: Burp Suite 같은 도구로 홈페이지 약점을 미리 점검
  * 차단은 신중히: 내부 직원이 공격 비슷한 신호를 보냈을 뿐인데 막으면 "인터넷이 안 돼요" 민원이 옴
     - 다른 기관 쪽에서 우리 IP를 막아 홈페이지 접속이 안 되는 일도 있음 → 정상인지 먼저 확인
  * 파견관제의 장점: 원격관제와 달리 사고 분석까지 직접 해볼 수 있어 다양한 경험을 쌓음

9. 파견관제의 훈련과 점검 — 쉽게 말하면 "소방 훈련"
  * 디도스 훈련: 공격 발생 장비로 실제 트래픽 폭탄을 보내 관제가 얼마나 잘 막는지 봄 (연 1~2회)
  * 도상 훈련: "악성코드가 모든 PC에 퍼졌다, 어떻게 할래?" 같은 상황을 받아 대응 방법을 써서 제출
  * 국정원 점검(공공기관·공기업, 연 1회): 기관 장비의 약점을 스캔해 점수를 매김 → 그래서 평소 점검을 열심히 함

10. 진로 참고 (일반 팁)
  * 신입은 근무 지역을 고르기 어려움. 채용공고에서 근무지를 보고 지원하는 게 현실적
  * 일자리는 서울·경기가 가장 많고 다음이 대전. 부산은 파견 사이트가 적음
  * 교대 근무가 많음: 주간 9~18시 / 야간 18시~다음날 9시 식. 휴가는 서로 겹치지 않게 미리 조율
  * 작은 사이트일수록 팀원 관계가 중요. 건강 관리 필수
  * 정보보안기사 자격증을 요구하는 곳이 많음

11. 꼭 기억할 것 (중요)
  * 사고조사는 "흔적 수집 → 시간순 정렬 → 직전에 뭐가 실행됐나" 순서
  * 휘발성 흔적(지금 연결 등)은 바로 사라지니 현장에서 먼저 수집
  * 악성코드는 자동 실행에 숨는다 → Autoruns에서 게시자 없는 수상한 항목 확인
  * Prefetch·MFT·이벤트 로그는 파일을 지워도 남는 '출입 기록'
  * 원격접속(RDP)·노출된 로그인 페이지는 해킹의 대표 출입구
  * 차단 전에 정상 사용자가 아닌지 꼭 확인

12. 과제 / 실습 / 공지
  * 실습: CIDER Collector 결과 열어보기, Autoruns·WinPrefetchView·레지스트리 분석 도구 직접 실행
  * 수업 폴더 도구: Autoruns, BrowsingHistoryView, ChromeCacheView, FTK Imager, JumpListsView, LastActivityView, Procmon, Sysinternals
  * 일부 분석 도구는 한 달만 무료 → 필요할 때 쓰고 지우는 방식 권장
  * 공지: 진흥원 저녁 행사(전체 카톡 안내 예정)는 참석 자유
  * 별도 과제 언급 없음
