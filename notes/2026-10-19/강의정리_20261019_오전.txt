2. 보안 일의 3가지 분야 — 쉽게 말하면 "경비원·형사·모의 도둑"
  * 보안관제: 24시간 교대로 화면을 보며 공격 신호를 찾는 일. 1차 방어선 (경비원)
  * CERT(침해사고 대응팀): 사고가 나면 원인 분석·피해 복구, 평소엔 사고 예방 (형사)
  * 모의해킹: 허락받고 일부러 공격해 약점을 미리 찾는 일 (모의 도둑)
  * 관제 경력이 쌓이면 CERT로 가는 경우가 많음

3. 파견관제 vs 원격관제 — 쉽게 말하면 "상주 경비원 vs 원격 CCTV 업체"
  * 원격관제: 보안회사 관제센터에서 고객사 로그를 받아 멀리서 봄. 주로 홈페이지 서버 위주
  * 파견관제: 고객 기관(시청 등)에 직접 가서 근무. 내부 서버·직원 PC까지 넓게 봄
     - 공공기관이 많이 씀: 중요한 로그가 밖으로 나가면 위험하기 때문
     - 비용은 더 비쌈 (자리 제공 + 전담 인력)
     - 내부 네트워크 구성을 잘 알아야 함. 관제 말고도 다른 보안 업무 요청이 많음

4. 보안 장비 — 쉽게 말하면 "건물의 여러 겹 경비 시스템"
  * 방화벽: 정문 출입 명단. 정해진 주소(IP)·문 번호(포트)만 통과
     - 사고 나면 "몇 시~몇 시에 누가 드나들었나" 기록을 검색하는 데 많이 씀
  * IPS(침입방지): 짐 검사대. 알려진 공격 모양(시그니처)과 비교해 막음
     - 새 공격이 나오면 시그니처를 계속 업데이트해야 함
  * WAF(웹 방화벽): 홈페이지 전용 경비. 암호화(HTTPS)된 내용도 풀어서 검사
  * 디도스 방어 장비: 한꺼번에 몰려드는 가짜 손님(트래픽 폭탄)을 막음
     - 기준(임계치)이 너무 높으면 공격이 통과, 너무 낮으면 정상 손님도 막힘
  * SIEM: 여러 장비의 로그를 한 화면에 모아 보기 좋게 정리 + 연관 분석
     - 예: "해외 IP 접속" + "다른 수상한 신호"가 겹치면 경고
  * TI(위협 정보): 이미 알려진 나쁜 IP·주소 목록. 여기 걸리면 바로 경고
  * EDR: PC·서버 안을 지키는 고급 백신. 파일뿐 아니라 '행동'(실행, 연결)까지 감시하고 격리·삭제
  * SOAR: 반복 작업 자동화 로봇. "이 IP 막아" 같은 일을 정해진 순서(플레이북)대로 자동 처리

5. 로그 읽는 법 — 쉽게 말하면 "택배 송장 읽기"
  * 실제 IPS·디도스·WAF·EDR 로그 화면을 봄. 주소가 암호처럼 인코딩돼 있으면 디코딩해서 읽음
  * WAF 로그의 주요 칸
     - 출발지 IP / 목적지 IP, 시간
     - 요청 방식(GET·POST 등). PUT·DELETE가 많이 오면 비정상 의심
     - 응답 코드: 200번대 = 성공, 404·500번대 = 실패
     - 응답 크기: 200(성공)인데 크기가 아주 작으면 실제론 실패했을 수 있음
     - User-Agent(접속 프로그램 정보): 사람이 아닌 로봇(검색 크롤러, ChatGPT·Gemini 같은 AI 봇)도 많음 → 너무 많으면 차단
  * EDR 사례: 원격조종 프로그램·개인 클라우드 사용을 탐지해 차단 (공공기관 자료 유출 방지)

6. 회사 네트워크 구조 — 쉽게 말하면 "건물 로비와 금고"
  * 순서: 인터넷 → 라우터 → 디도스 장비 → 방화벽 → DMZ → IPS·WAF → 서버
  * DMZ(비무장지대): 외부인도 들어올 수 있는 로비. 홈페이지·메일·DNS 서버가 있음
  * 내부 서버(DB 등)는 금고. 방화벽을 한 겹 더 두고 정해진 1~2명만 접근
  * 직원 PC에서 밖으로 나가는 원격접속(RDP, 3389번 포트)도 막음 → 감염 PC가 밖으로 연결 못 하게
  * 방화벽이 빠진 잘못된 구성이면: DMZ 서버 하나 뚫림 → 직원 PC → 내부 서버까지 줄줄이 뚫림
  * 망분리: 인터넷용 PC와 업무용 PC를 아예 나눔. 자료는 '망연계 시스템'으로만 주고받음
     - 망연계에 약점이 있으면 여기를 통해 내부 DB까지 뚫린 실제 훈련 사례가 있음

7. 판단 연습 — 쉽게 말하면 "단서가 늘 때마다 추리를 고치는 탐정"
  * 공격 시도만 보고는 성공·실패를 모름 → 단서를 하나씩 더함
     - 응답 404 → 실패 / 응답 200 → 추가 확인 필요
     - 출발지가 내부 직원 IP → 정상일 가능성 / 해외 IP → 공격 가능성
  * 예: 서버에 '파일 내려받기(wget) → 이름 앞에 점(.) 붙여 숨김 → 실행 권한 주기' 명령이 들어옴
     - 리눅스에선 이름이 점으로 시작하면 숨김 파일 → 악성 파일일 가능성 큼
     - 관제는 서버에 직접 못 들어감 → 방화벽 로그에서 그 주소와 실제 통신했는지 보고 성공 여부 판단
  * Base64로 숨긴 명령은 꼭 디코딩해서 내용을 확인

8. 실제 내부 사고 사례 — 쉽게 말하면 "도둑은 안에도 있다"
  * 직원이 IPS 탐지 규칙을 몰래 빼내 이직하려다 적발 → 국정원 조사, 징계
  * 업무 자료를 외부 저장공간에 올렸다가 대량 탐지·징계
  * P2P로 받은 파일을 USB로 들여옴 → USB 자동 실행으로 PC 감염
  * 원격조종 프로그램(TeamViewer·AnyDesk 등)을 켜 둔 채 방치 → 해외에서 접속 → 랜섬웨어
     - 유지보수 개발자가 편하려고 설치를 요구하는 경우가 많음
  * 몰래 USB 무선랜으로 따로 인터넷 연결 → P2P·게임 → 북한 해킹조직 악성코드 → 국정원 조사
  * 파견 근무자는 자리를 오래 비우면 안 됨 (계약에 불이익)

9. 증거 수집 도구 첫 실습 — 쉽게 말하면 "감식 장비 개봉"
  * CIDER Collector: 국산 사고조사 수집 도구. 실행에 시간이 꽤 걸림 (결과 분석은 오후)
     - 사이버수사대는 PC 속 범죄 증거 수집에 외국산 도구(EnCase)를 많이 씀
  * FTK Imager: 디스크를 통째로 복사(이미지)해 다른 PC에서 분석. 경찰도 많이 씀
     - 논리 드라이브(C·D) / 물리 드라이브(SSD 자체)
     - 휴지통·최근 삭제된 파일(X 표시)과 만든·고친 날짜까지 보임
  * hosts 파일 (C:\Windows\System32\drivers\etc\hosts): PC의 '개인 주소록'
     - 원래는 DNS(전화번호 안내)에 물어서 사이트 주소를 찾음
     - 악성코드가 여기에 "네이버 = 가짜 서버" 를 적으면 → 가짜 로그인 화면 → 비밀번호 도난
     - 같은 비밀번호를 여러 곳에 쓰면 피해가 커짐

10. 내 필기 메모 (녹음에선 확인 어려운 부분)
  * 클라우드: 남의 설비를 빌려 쓰는 것. 이유는 비용·시간·기술 / 온프레미스: 내 설비를 직접 보유
  * VPN: 공용 인터넷 위에 만든 '비밀 전용 통로'
  * 서버 가상화: 컴퓨터 한 대를 여러 대처럼 나눠 써서 자원 절약·비용 절감

11. 꼭 기억할 것 (중요)
  * 관제 = 24시간 1차 방어, CERT = 사고 분석·복구
  * 장비마다 역할이 다름: 방화벽(출입명단), IPS(짐검사), WAF(웹 전용), EDR(PC 감시), SIEM(로그 모음), SOAR(자동화)
  * 응답 코드 200 = 성공, 404·500 = 실패. 단, 응답 크기까지 같이 볼 것
  * 단서 하나로 결론 내지 말고, 정보가 늘 때마다 다시 판단
  * 내부 서버는 방화벽 한 겹 더 + 정해진 사람만 접근
  * 원격조종 프로그램·USB·P2P·몰래 인터넷은 실제 사고의 단골 원인
  * hosts 파일이 바뀌면 가짜 사이트로 끌려갈 수 있음

12. 과제 / 실습 / 공지
  * 실습: CIDER Collector 실행(결과는 오후에 분석), FTK Imager로 C드라이브 살펴보기, hosts 파일 메모장으로 열어보기
  * 별도 과제 언급 없음
